## Sample Exercise

To validate the installation of the environment and understand how to complete this book's programming exercises with the help of an automated checker, we can attempt to complete the following dummy exercise.
The objective is simple: create an empty C program doing nothing in particular, and submit it to our automated checker.

### Creating our Empty C Program

Create a file named `sample-exercise.c` and write this code inside:

```c
int main() {
    return 0;
}
```

> **Per-Exercise Folders.**
> For the automated checker to work properly, it is recommended to place the source file(s) developed for each exercise within a separate, per-exercise, folder.

This program is made of a `main function (entry point) that returns directly without doing anything.
It should compile sucessfuly, and when executed the resulting binary should not output anything:

```console
$ gcc sample-exercise.c -o sample-exercise
$ ./sample-exercise
$
```

### Submitting the Code to the Automated Checker

To submit the code, type or copy-paste the following command in the local directory containing the source code:

```console
$ check50 01-intro/01-sample
```

Here, `check50 is our automated checker, and the sample exercise we are attempting to complete here is uniquely identified with the following path: `01-intro/01-sample`

For each exercise presented in this book, the instruction will detail what specific path should be given to `check50 to trigger the automated checks.
Also note that for each exercise, the submitted source file should have a specific name (here it is `sample-exercise.c`), which will be also given in the instructions.
`check50` will display on the command line the various checks realised on the submission, and their success/failure:

```console
Checking.......
Results for c-programming-essentials/exercises/main/01-intro/01-sample generated by check50 v3.4.0
:) exists
    checking that sample-exercise.c exists...
:) compiles
    running gcc sample-exercise.c -o sample-exercise -std=c11 -ggdb -lm...
:) output correct
    running ./sample-exercise...
    checking for output ""...
```

Each check's result is indicated with a smiley:

\begin{itemize}
    \item A happy smiley `:)` indicates success.
    \item An unhappy one `:(` indicates failure.
    \item A neutral one `:|` indicates an internal \texttt{check50} error.
\end{itemize}

In the case of our sample exercise, a series of happy faces should be printed on the command line as illustrated above, indicating that all checks passed.

Each check is briefly described on the command line, which should help for debugging in case certain checks fail.
